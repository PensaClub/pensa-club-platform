## Публичен потребителски flow

### 1. Начална страница (`/reaction`)

Компонент: `ReActionProgram`

- Hero секция с описание на програмата
- Статистики (завършени посещения, градове, клубове)
- Одобрени отзиви от клубове
- Бутон за подаване на заявка

### 2. Попълване на формата за заявка

Компонент: `ReActionBookingForm`

| Поле | Тип | Задължително |
|------|-----|:---:|
| Име на клуб | текст | да |
| Град | текст | да |
| Брой участници | число | да |
| Тема | dropdown | да |
| Друга тема (ако е "друга") | текст | условно |
| Предпочитана дата | календар | да |
| Лице за контакт | текст | да |
| Телефон | текст | да |
| Имейл | текст | да |
| Бележки | текст | не |

**Теми за избор:**
- Фалшиви новини
- Избирателни права
- Изборен процес
- Друга

**Календар:** Показва само дати, за които има наличен поне 1 ментор. Заетите дати са неактивни.

### 3. Защита от дублирани заявки

При изпращане сървърът проверява за активна заявка (статус: new, reviewing, mentor_assigned, confirmed):
1. По `userId` (ако е логнат)
2. По `contactEmail`
3. По `contactPhone`

При намерен дубликат:
- Показва жълт банер с код на съществуващата заявка
- Линк "Проследи заявката" → `/reaction/track/{код}`
- Линк "Управление на заявките" → `/reaction/my` (само за логнати)
- Опитът **не се брои** в rate limiter-а

### 4. Успешно изпращане

- Получава **tracking код** на екрана
- Получава имейл потвърждение
- Ако е логнат — заявката се свързва с потребителския акаунт (`userId`)

### 4. Проследяване на заявка (`/reaction/track` или `/reaction/track/{код}`)

Компонент: `ReActionTrack`

- Въвежда tracking кода (или кодът идва от URL-а)
- Вижда: статус, име на клуб, дата, тема, дата на подаване
- Timeline визуализация на статусите
- Директен линк `/reaction/track/{код}` зарежда и търси автоматично

### 5. Отмяна на заявка от проследяване

При активна заявка (статуси: `new`, `reviewing`, `mentor_assigned`) на страницата за проследяване:
- Бутон "Отмени заявката" (достъпен за всички — логнати и нелогнати)
- Отваря модал с потвърждение и опционален textarea за причина
- При потвърждение:
  - Статусът става `cancelled`
  - Потребителят получава имейл потвърждение за отмяната
  - Админът получава нотификация
  - Ако има назначен ментор — получава имейл
  - Ако заявката е свързана с акаунт — потребителят получава и in-app нотификация
- За логнати потребители се показва и линк "Управление на заявките" → `/reaction/my`

## Логнат потребител flow

### Pre-fill на имейл

Когато логнат потребител отвори формата за заявка:
- Полето `contactEmail` се попълва автоматично с имейла от профила
- Показва се подсказка: "Имейлът от вашия профил е попълнен автоматично. Можете да го промените."
- Потребителят може свободно да промени имейла

### Моите заявки (`/reaction/my`)

Компонент: `ReActionMy` (изисква логин)

**Статистики:**
- Общо заявки
- Активни
- Завършени
- Отменени

**Секции:**

| Секция | Описание | Статуси |
|--------|----------|---------|
| Предстоящи посещения | С потвърдена/назначена дата в бъдещето | `confirmed`, `mentor_assigned` |
| Активни заявки | Нови или в преглед | `new`, `reviewing` |
| История | Завършени и отменени | `completed`, `cancelled` |

**Карта на заявка показва:**
- Статус badge (цветен)
- Tracking код
- Име на клуб
- Град + дата
- Ментор (ако е назначен)

**Отмяна на заявка:**
- Бутон "Отмени" (достъпен при статуси: `new`, `reviewing`, `mentor_assigned`)
- Отваря модал с опционален textarea за причина
- При потвърждение:
  - Статусът става `cancelled`
  - Админът получава нотификация
  - Ако има назначен ментор — получава имейл

**Бутони:**
- "Подайте заявка" → `/reaction`
- "Към профила" → `/profile`

### Потребителски нотификации

Логнатите потребители получават in-app нотификации (камбанка в навигацията):

| Тип | Кога се създава |
|-----|-----------------|
| `reaction_request_status_changed` | Админ смени статуса на заявка |
| `reaction_mentor_assigned` | Ментор е назначен на заявка |
| `reaction_visit_confirmed` | Ментор потвърди посещение |
| `reaction_visit_reminder` | 2 дни преди посещение (cron) |

Клик на нотификация → `/reaction/my`

## Админски flow

Компонент: `AdminReAction` — 4 таба

### Таб 1: Календар

Компонент: `AdminReActionCalendar`

- Месечен изглед с навигация напред/назад
- Всеки ден показва:
  - Цветни точки за заявки (по статус)
  - Брой налични ментори
- Цветова легенда:
  - Зелено = има налични ментори, няма заявки
  - Жълто = частично заето
  - Червено = напълно заето
- Клик на ден → детайли:
  - Списък заявки с клуб, статус, ментор
  - Списък налични ментори
- Мобилен изглед: списък вместо grid

### Таб 2: Заявки

Компонент: `AdminReActionRequests`

**Филтри:**
- Статус (dropdown)
- Град (текстово търсене)
- Свободно търсене
- Дата от / до

**Таблица:**

| Колона | Описание |
|--------|----------|
| Дата | Предпочитана дата на посещение |
| Клуб | Име на клуба |
| Град | Град |
| Тема | Избрана тема |
| Статус | Цветен badge |
| Ментор | Назначен ментор (ако има) |
| Действия | Бутон за преглед |

**Действия:**
- Експорт в CSV (с текущите филтри)
- Изчистване на филтри
- Пагинация (по 20)
- Мобилен изглед: карти вместо таблица

**Клик на заявка → Модал** (`AdminReActionRequestModal`):
- Ако заявката е от регистриран потребител — показва лилав badge "Регистриран потребител: {email}"
- Преглед на всички данни за заявката
- Смяна на статус (dropdown)
- Назначаване на ментор (dropdown с налични за датата ментори)
- Админ бележки (textarea)
- Причина за отказ (при статус "отказана")
- Бутон "Изпрати имейл" → отваря `AdminReActionEmailModal`
- Бутон "Изтрий заявка"
- Бутон "Запази"

**Имейл модал** (`AdminReActionEmailModal`):
- Получател (автоматично от заявката)
- Тема
- Съобщение
- Изпращане

### Таб 3: Статистики

Компонент: `AdminReActionStats`

**Обобщени карти:**
- Общо заявки
- Завършени посещения
- Чакащи заявки
- Активни ментори

**Разбивки:**
- По статус (progress bars)
- По месец (bar chart)
- Топ градове (класация)
- Топ теми (класация)

### Таб 4: Отзиви

Компонент: `AdminReActionTestimonials`

**Таблица:**

| Колона | Описание |
|--------|----------|
| Клуб | Име на клуба |
| Град | Град |
| Цитат | Текст на отзива |
| Автор | Име на автора |
| Статус | Одобрен / Чакащ |
| Действия | Одобри/Откажи, Редактирай, Изтрий |

**Действия:**
- Добавяне на нов отзив (форма: клуб, град, цитат, автор, одобрен)
- Редактиране
- Превключване одобрен/неодобрен с един клик
- Изтриване (с потвърждение)
- Мобилен изглед: карти

## Менторски flow

Компонент: `MentorReAction` — 4 таба

### Таб 1: Календар

Компонент: `MentorReActionCalendar`

- Месечен изглед
- Клик на ден → превключва наличност (наличен ↔ неналичен)
- Цветове:
  - Зелено = наличен
  - Червено = неналичен
  - Синьо = назначено посещение
  - Сиво = неотбелязан
- Бързи действия:
  - "Маркирай всички делнични дни" — отбелязва Пон-Пет като налични
  - "Изчисти месеца" — маркира всичко като неналично
- Минали дати са неактивни
- Бутон "Запази промените" (показва се при несъхранени промени)

### Таб 2: Назначения

Компонент: `MentorReActionAssignments`

Карти за всяко назначено посещение:

| Поле | Описание |
|------|----------|
| Дата | Предпочитана дата |
| Статус | Назначен / Потвърден |
| Клуб | Име на клуба |
| Град | С икона за локация |
| Тема | Badge |
| Участници | Очакван брой |
| Контакт | Име, телефон (кликаем), имейл (кликаем) |
| Бележки | Ако има |

**Действия:**
- "Потвърди" (при статус `mentor_assigned`) — изпраща имейл до клуба
- "Докладвай проблем" → модал с textarea → изпраща нотификация и имейл до админа

### Таб 3: История

Компонент: `MentorReActionHistory`

**Таблица:**

| Колона | Описание |
|--------|----------|
| Дата | Дата на посещение |
| Клуб | Име на клуба |
| Град | Град |
| Тема | Badge |
| Участници | Реален брой (от feedback) или очакван |
| Рейтинг | Звезди (1-5) |
| Обратна връзка | Покажи/Скрий детайли или Добави |

Разширяеми детайли: покрити теми, предизвикателства, акценти, препоръки.

Мобилен изглед: карти.

### Таб 4: Обратна връзка

Компонент: `MentorReActionFeedbackForm`

Достъпен от историята (бутон "Добави обратна връзка"):

| Поле | Тип | Задължително |
|------|-----|:---:|
| Реален брой участници | число | не |
| Покрити теми | textarea | не |
| Предизвикателства | textarea | не |
| Акценти | textarea | не |
| Препоръки | textarea | не |
| Рейтинг | 1-5 звезди | не |

## Статуси на заявка

```
new → reviewing → mentor_assigned → confirmed → completed
                                                    ↘ cancelled (от всеки статус)
```

| Статус | Описание | Цвят |
|--------|----------|------|
| `new` | Нова заявка, непрегледана | оранжев |
| `reviewing` | Преглежда се от админ | син |
| `mentor_assigned` | Назначен ментор, чака потвърждение | лилав |
| `confirmed` | Менторът потвърди посещението | зелен |
| `completed` | Посещението е завършено | сив |
| `cancelled` | Отказана | червен |

## Имейл нотификации

| Събитие | Получател | Описание |
|---------|-----------|----------|
| Нова заявка | Админ | Уведомление за нова заявка |
| Потвърждение от подаване | Клуб (contactEmail) | Tracking код + детайли |
| Назначен ментор | Ментор | Детайли за посещението |
| Ментор потвърди | Клуб (contactEmail) | Потвърждение с дата и тема |
| Отказана заявка | Ментор (ако е бил назначен) | Причина за отказ |
| Докладван проблем | Админ | Съобщение от ментор |
| Ръчен имейл | Клуб (contactEmail) | Свободен текст от админ |
| Потребител отмени заявка (от /my) | Ментор (ако е назначен) | Причина за отказ |
| Отмяна по tracking код | Клуб (contactEmail) | Потвърждение за отмяна |
| Отмяна по tracking код | Ментор (ако е назначен) | Уведомление за отмяна |

## Потребителски нотификации

| Тип | Получател | Кога | Иконка |
|-----|-----------|------|--------|
| `reaction_request_status_changed` | Подал заявката | Админ смени статус | 🔄 |
| `reaction_mentor_assigned` | Подал заявката | Назначен ментор | 🤝 |
| `reaction_visit_confirmed` | Подал заявката | Ментор потвърди | ✅ |
| `reaction_visit_reminder` | Подал заявката | 2 дни преди посещение | ⏰ |

Нотификации се създават **само** ако заявката има `userId` (подадена от логнат потребител).

## Анти-спам защити

| Ниво | Защита | Описание |
|------|--------|----------|
| Клиент | Honeypot поле | Скрито поле — ботове го попълват, хора не |
| Клиент | Timestamp проверка | Формата трябва да е отворена поне 3 сек |
| Клиент | Rate limit (localStorage) | Макс 3 заявки на час |
| Сървър | Honeypot проверка | Ако `_hp` е попълнено → фалшив success |
| Сървър | Timestamp проверка | Ако < 5 сек → фалшив success |
| Сървър | Rate limit (in-memory) | Макс 3 **успешни** заявки на час по IP |
| Сървър | Дублирани заявки | Проверка по userId → email → phone |

**Важно:** Rate limiter-ът брои **само успешно създадени** заявки. Дубликати, валидационни грешки и прекъснати заявки не се броят.
